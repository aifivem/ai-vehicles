# ai-vehicles

Owned vehicles: storage, ownership (characters, jobs, gangs), spawning on the server and the look (props, applied by ai-core on the entity's owner client). The API garages, shops, keys and fuel build on; stands in for `qbx_vehicles`. Depends on ai-core and its table through `@aifivem/mysql`.

## Decisions

- Memory first (`server/store.ts`): ids are assigned by the server (`MAX(id) + 1` at start), so `CreateVehicle` is synchronous; every change goes to the database in order through one write queue. The plate comes from the id (`AI` + base 36), so plates never collide.
- In memory: vehicles of online characters (loaded at join through lib `onCharacter`, registered once the tables and fleets are ready so its replay also loads the characters already in the game; dropped at leave unless still in the world) and every job / gang fleet (loaded at start). Exports only see those; offline characters' vehicles stay in the database.
- Spawning is lib `spawnVehicle` (server side, strict lockdown; the spawn type comes once per model from the asker's client through ai-core) with the keys for the caller's purpose (default `garage`). The entity gets the state bags `ai:owned`, `ai:vid`, `fuel` and `ai:props`; ai-core's client on the entity's owner applies the props (any resource's `spawnVehicle({ props })` works the same).
- An owned vehicle whose entity disappears while out goes to the impound state.
- Saving is split (owner decision: only ai-mechanic changes tuning): `SaveVehicle` saves condition and look but keeps the stored `mods` and `neon` (none without stored props), so a client-read look (garage parking) never persists a mod menu; `SaveTuning` saves full props and is called only by ai-mechanic. The qbx_vehicles `SaveVehicle` stand-in saves full props, mods and neon included (owner decision: Qbox garages and tuning scripts send them and rely on them): it takes the lib's VehicleProps or ox_lib / qb-core's props shape (`server/qbx/props.ts` turns `modEngine`, `color1`, ... into VehicleProps) and, like ai-mechanic's `SaveTuning` path, refuses props whose model is not the entity's (state and garage still save); the plate is always the vehicle's own. `GetPlayerVehicle` still hands out the lib's VehicleProps shape, not ox_lib's.
- Left vehicles (`server/cleanup/`, panel tab "Left vehicles", `data/settings.json`, `sync: "admin"`): one `every` job at the panel's interval walks the loaded players (`vehicleOf`), never every vehicle (only once at start, to read the deadlines back). A networked vehicle whose player driver is gone at a scan gets a deadline (`abandonMinutes`, `garageMinutes` on a panel garage spot) in memory and in the entity bag `ai:abandonAt` (epoch ms, so a restart of this resource keeps it); a player driver clears it; a vehicle with a player inside, a trailer or train (`GetVehicleType`) or a panel-blacklisted model is never removed; scope "unowned" skips vehicles in `world`. A ride shorter than one scan interval is not seen (detection is server-side only, no client event).
- An abandoned owned vehicle goes through lib `garages`: setting `ownedTo` "garage" stores it in the garage id of the spot it stands on, else (or when refused) `garages.impound`; when no garage script takes it, its condition is saved and the entity deleted, so `world.removed` puts it in the impound state like any lost owned vehicle. Garage spots are the panel's own list (defaults: ai-garages' public garages with their keys), because no lib / ai-core query for garage areas exists.
- Ambient vehicles a player drives get orphan mode 2 at the scan (`keepDriven`), so OneSync does not delete them when no player is near; `spawnVehicle` already does it for server-created ones. The left-vehicle cleanup is what removes them later.
- `SpawnVehicle(..., setup)` keeps a lib `VehicleSetup` (column `setup`) on a vehicle without props and applies it on every spawn until the first props save (ai-vehicleshop's colour on a vehicle that was never parked); stored props always win.

## Contracts

- Types and export signatures: `@aifivem/shared` `vehicles.ts` (`AiVehiclesServerExports`, `VEHICLE_BAGS`).
- qbx_vehicles exports: `server/qbx/index.ts` (citizenid filters need the owner online).
- Plate -> owner mirror for other resources (ai-vehiclekeys): export `GetPlateOwners()` -> `[plate, ownerType, ownerId][]` (every vehicle in memory, read once at the consumer's start) and the local server event `ai-vehicles:owners (puts, removes)` (`OWNERS_EVENT` in `resource/common/vehicles.ts`): vehicles that entered memory or changed owner as the same triples, plates that left memory; one batch per tick (`server/ownerFeed.ts`, fed by the store's add / forget). Neither is in `@aifivem/shared` yet.
- Props come in as the lib's VehicleProps or ox_lib / qb-core's shape (`CreateVehicle`, `SaveVehicle`, `SaveTuning`: `readAnyProps`); `GetVehicle` / `GetVehicles` / `FindVehicle` / `GetVehiclesOf` with `shape` "framework" hand them back in that shape (`toFrameworkProps`, `qbx/props.ts`) with `fuelLevel`, for scripts that spawn and dress vehicles themselves (TGIANN scripts).
- Owners who are not online: `FindVehicle(plate, done)` and `GetVehiclesOf(owner, done)` read the table (memory first, rows not loaded). `SetPlate(id, plate, done)`: a custom plate (1-8 letters / digits) for a vehicle in memory, checked against memory and the table; generated `AI...` plates are reserved, so the two never collide.
- `DeleteVehicleByPlate(plate, done)` (admin `/vehdel`): the row (memory, else the table: offline owners too) and every world entity with the plate; `done(DeleteByPlateResult)` (`@aifivem/shared`, typed in `AiVehiclesServerExports`). `DeleteVehicle(id)` and qbx `DeletePlayerVehicles` share `api.deleteVehicle` (memory only).
- Table `ai_vehicles_owned` (`sql/main.sql`).

## Entry points

- Store `resource/server/store.ts`, its SQL and row parser `server/repo.ts`; character vehicles load / unload `server/characters.ts`; entities `server/world.ts`; API `server/api.ts`, own exports `server/exports.ts`, delete by plate `server/deleteByPlate.ts`; panel `server/schema.ts` / `server/content.ts`; left vehicles `server/cleanup/` (scan `abandoned.ts`, end state `remove.ts`, settings and default spots `settings.ts`).
